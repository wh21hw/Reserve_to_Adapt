# UPUK 对 RTA + IMP 的借鉴

2026-10-05。毕业设计可明确借鉴已有思想，重点是实现合理、增量清楚、消融支持；不要求把自适应K或交替训练包装为全新范式。本文为方法阅读与下一版建议，未启动UPUK复现或新训练。

## 论文实际做了什么

1. 在source预训练特征上，用独立的unknown diffuser学习target簇分配。初始簇数等于已知类数，但“初始数量相同”不等于每个簇已经具有已知类身份。
2. 主簇与二分子簇分别学习分配；距离提出分裂/合并候选，M-H框架决定是否调整簇数。这里不是只超过一个距离阈值就认定新语义，也不是图像生成式diffusion。
3. 已知知识的可靠性通过选择低熵target和对比约束增强；正文采用低熵前50%，这是一种启发式，不是可移植的已知比例保证。
4. 在发现的较大类别空间内，用可靠已知伪标签约束簇身份，再用聚类分配约束进行学习。发现结构与特征/模型学习相连接，不只是输出一个容量数字。

**符号不能混用**：UPUK的K表示target总簇数；本项目RTA的C是已知输出数，K是未知输出槽，Q是目标聚类数，V是虚拟方向数。即使推断总簇数减C，也要先确认簇身份；域移位导致的已知碎裂会被误算成未知容量。

## 代码中可直接借鉴的接口思想

`obtain_label_dpm`先构造已知伪标签；低置信样本标记为未可靠确认。随后先推断簇数，再在该数量下进行带伪标签的优化。`target_train.py`用预测与簇分配的Hungarian匹配一致性筛可靠已知训练样本，且保留无一致样本时的fallback。

这不是“直接训练C+K未知头”的完整实现：主入口仍冻结C维source分类器，另一套diffuser处理簇空间。需要分开解释论文Algorithm 1、发布主入口与我们的RTA未知槽，不能把它们当同一接口。

其聚类调用同时传入真实target标签用于评估的数据通路，后端是否影响拟合需要进一步核查。本项目不会直接复用这条通路：结构拟合只接收特征与模型预测，真实标签隔离在事后诊断。仅看到评估标签参数不据此断言论文泄漏。

## 对我们当前问题的意义

我们的source-stage IMP把大量target已知分为候选新簇，说明“新簇身份”尚不可靠；仅把K送进RTA也没有保留发现的分配。UPUK提示要让可靠已知知识与target簇结构互相核对，而不是把全部远离source的簇直接当未知。

该启示不是已经证实的修复：source分类器也会自信地误判未知；几何与分类器也可能共同犯错。不能靠置信度保证安全，更不能硬设已知比例为50%或把大簇自动当已知。

## 建议的简化毕业设计版本（待实验）

保留ResNet/RTA、IMP容量与source监督。借鉴UPUK的可靠身份约束，不立即移植500轮diffuser、子网络、M-H和新对比损失。

流程：source C维预热 → 当前target结构发现 → 可靠已知身份确认/保留未确认状态 → 未知簇与RTA未知槽对应 → 可靠结构伪标签训练 → 预声明阶段重估结构。

先在固定K和共同初始化下，单独比较：

- 原版未知argmax伪标签。
- 既有簇身份桥接。
- 可靠身份保护版本：分类器与结构对已知身份一致的样本不被未知伪标签强拉；冲突样本暂不提供未知CE标签，不能直接改成已知训练标签。簇身份对应不得依据真实target标签。

第三项会改变未知伪标签采信门控，不再叫K-only；与单纯簇身份桥接分开报告。第一项实验先检验互相吸入是否降低，再研究动态K；本阶段不同时改预测规则、头初始化或加新损失。

阈值和可靠性规则必须在运行前声明，依据source留出代理/无标签一致性，而非target HOS选择。衡量覆盖率、冲突率、未知槽利用、OS*/UNK/HOS，以及隔离的事后簇组成；只提高拒识或只减少K均不算成功。

当前VisDA十轮照常完成，随后用预声明fixed2 final10特征诊断定位表示与头的问题。新脚本 `scripts/extract_visda_final_geometry_colab.py` 已上传，CPU严格加载真实final10 checkpoint和输入维度检查通过；尚未执行GPU特征提取，避免与现有训练并发。

## 后续实际诊断：不能在塌缩后依靠严格门控恢复

VisDA十轮与一次final特征提取现已完成，具体结果见 `visda_protocol_v1/FROZENBN_CAPACITY_V1.md`。随后在缓存上运行一次source校准可靠身份候选规则，不进行GPU前向、新训练或target调参：

- source各类距离99%分位作为类内范围。
- source真实类别的已知条件概率1%分位作为置信下限。
- target最近source原型身份与已知输出内argmax身份一致、距离/置信均满足才保护。
- 已知条件概率只对C个输出归一化，不要求已知输出先战胜已塌缩的未知头。

`reliable_known_guard.py`不接收真实target标签；事后标签检查位于独立probe的规则计算之后。final缓存上仅21张被保护，全部为已知，但已知覆盖率仅0.06150%，这21张的已知身份精度为66.67%。未知误保护为0不能称优秀，因为规则几乎不覆盖数据。这是失败状态的机制探测，不是早期门控训练的有效性实验，也不是无标签阈值最优性证明。

下一步改变：若实验身份保护，必须在预声明早期节点启用，而不是把final坏表示重新聚类再期待恢复；监测保护覆盖率与冲突率，不把更保守、更少覆盖等同改进。候选规则暂不接入训练，也不根据这次target组成放宽阈值。需要同预算早期干预对照才可判定它是否能防止塌缩。
