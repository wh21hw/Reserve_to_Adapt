# 源域先验总权重消融（尚无真实数据结果）

2026-10-05，针对已观察到的“已知目标样本形成候选未知簇”，准备单因素接口，不按目标标签删除簇。

当前目标拟合项的每样本权重为 R/N_target，总权重 R；源类中心精度为各类 anchor 样本数 n_c，总和为 C·R。因此允许已知中心移动，并不等于源域和目标域影响相当。这里存在一个待检验假设：强先验让已知中心难以随域偏移移动，部分已知结构被误建为新簇。它不是已经确定的退化原因。

接口 source_precision_capacity.estimate_source_cost_capacity 的 prior_mass_mode 默认为 source_counts，原数值不变；显式 domain_balanced 使用 κ_c=n_c·R/Σn_c，将源域先验总权重降为 R。半径、建簇成本、source70/15拆分、随机状态2026、birth-first、参考样本数、特征及其余算法均不变。仍是经验加权聚类目标，不声称完整贝叶斯后验或唯一理论正确设置。

注意 birth-first 在移动中心前可能先建簇，两组初始建簇提案相同；降低先验不保证最后少建簇，也可能把真实未知吸入已知中心。后续真实特征对照必须同时看纯已知负对照的误建，以及已知+留出源类正对照的未知检出/误接收，不能只看 K 变小。沿用 C20、留出源类0..4、source frozen-BN CE3 的既有特征及固定拆分，不将更容易的其他任务替代该实验。源类标签只定义源域代理评价，不使用 target 语义标签。

当前只准备接口并做一次功能检查；C20 真实特征位于已消失 runtime，恢复前不运行真实对照，不重训、不修改 VisDA 已启动研究设置。若对照支持该机制，再单独考虑 target 容量与 RTA 消融；新开关不自动启用于任何历史 launcher。

接口检查已通过 scripts/check_prior_mass_interface.py：与 Git HEAD 的原实现对比，默认中心、样本分配和优化 history 相同；domain_balanced 保持半径/成本/拆分/R不变，精度总权重比由 C 降到1；非法模式拒绝。小型输入只检验接口与默认兼容性，不是该研究假设的验证，不代替 C20 的真实特征正负对照。
